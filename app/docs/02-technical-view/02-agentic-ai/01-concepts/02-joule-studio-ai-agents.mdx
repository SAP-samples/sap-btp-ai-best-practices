This best practice focuses on creating **AI agents with Joule Studio** and deploying them to the **SAP-managed Joule Studio runtime**. For agents that you build, host and operate yourself in your own SAP Business AI Platform subaccount, see the <Link to={useBaseUrl("/docs/technical-view/agentic-ai/concepts/pro-code-ai-agents")}>Pro-Code: Creating AI Agents</Link> best practice.

## <span className="step-number">1</span> <span className="step-title">Overview</span> {#1-overview}

### Description

Joule Studio is SAP's AI-native development environment for building agents, applications and workflows as part of SAP Business AI Platform. Agents built with Joule Studio are Python-based. Joule Studio uses a structured approach called **Intent-Based Development (IBD)** to start with a user's intent and produce a working Python-based AI Agent. The Agent is deployed in an SAP-managed runtime, registered with Joule Work automatically and becomes available to users in Joule Work.

Joule Studio offers two design-time surfaces:

- **Browser flow**: Joule Studio's Intent-Based Development (IBD) runs in your browser with no local setup required.

- **Pro-Code Flow**: Joule Studio's Command Line Interface ([**jl**](https://www.npmjs.com/package/%40sap/joule-studio-cli?activeTab=readme)) couples with a coding agent (Claude Code or OpenCode), which leverages Joule Studio's IBD skills and Joule Studio's Model Context Protocol (MCP) server to run the IBD flow locally.

Joule Studio uses Intent-Based Development (IBD) as a structured, phased approach for building agents, applications and workflows. It starts with a user's intent (input prompt) and ends with a deployed solution containing various artifacts. The six phases of IBD are below:

| **Phase** | **Description** |
| --- | --- |
| 01 Intent | The user describes the expected business outcome and Joule Studio refines the intent by asking clarifying questions |
| 02 Requirements | A Product Requirements Document (PRD) is generated by utilizing SAP Knowledge Graph and SAP domain models for business context |
| 03 Specification | The PRD is translated into a technical blueprint based on the customer landscape by utilizing LeanIX |
| 04 Solution | Joule Studio's coding assistant generates code based on the specification |
| 05 Testing | Unit tests and AI evals are automatically generated to evaluate the solution against the requirements |
| 06 Deployment | User can trigger a one-click deployment to the SAP-managed Joule Studio runtime |

You can leverage the [Ideation Agent](https://ai4u-website.cfapps.eu10-004.hana.ondemand.com/ideation-agent) to come up with a high-quality initial intent.

Joule Studio capabilities that are generally available (GA) include agent creation, standard agent extension using instructions, and MCP server creation. [Roadmap items](https://roadmaps.sap.com/board?PRODUCT=73554900100800006746&range=CURRENT-LAST#Q4%202026) include n8n workflows, applications built using CAP and Vercel, and Data Product creation in SAP Business Data Cloud.(As of November 2026)

### Expected Outcome

After following this best practice, developers will be able to:

- Decide when to build and deploy agents using Joule Studio versus using the Pro-Code option in SAP Business AI Platform

- Decide when to use browser flow, local flow, or a hybrid approach for creating AI Agents

- Apply the Intent-Based Development approach and ensure that the intent, PRD, specification, and code are kept consistent.

- Test, evaluate, and govern agents running on the SAP-managed Joule Studio runtime.

### Benefits

- **Zero infrastructure operations:** Business AI Platform account setup, runtime configuration, storage and model access are provided by SAP. Users spend their effort on agent logic and tool design, not on platform plumbing.

- **Business context from day one:** SAP Knowledge Graph and SAP Domain Models provide business and API context, and SAP LeanIX provides the customer's landscape, including third-party applications. Generated specifications are grounded in the customer's landscape and business context.

- **Traceability from intent to code:** Every agent carries its intent, PRD, specification, code and tests as one chain. This is a strong audit and handover asset, provided it is kept in sync (see Section 3).

- **Enterprise controls built in:** Each agent runs isolated with configurable policies. Identity, principal propagation and policy enforcement are handled centrally by Agent Gateway. Telemetry and audit logging come from the runtime.

- **Developer freedom within guardrails:** Developers can utilize their own developer tools (IDE), coding agent and Git workflow. The guardrails apply to a set of contract files and patterns, while developers retain the freedom to modify the business logic.

- **Native Joule integration:** Deployed agents register with Joule Work automatically, so users reach them in Joule Work without any separate integration project.

### Key Concepts

- **Solution and Asset:** A solution is the deployable unit that can contain one or more assets that solve a business problem. Asset types include agents, agent extensions, MCP servers, and n8n workflows, with more asset types planned for the future.

- **Intent-Based Development (IBD):** SAP's structured, AI-driven workflow that turns a natural-language business intent into a PRD, a technical specification, code, tests and a deployment. IBD utilizes the SAP Knowledge Graph, SAP LeanIX and SAP Domain Models to generate a solution in Joule Studio.

- **IBD Skills:** IBD Skills are design-time instruction sets loaded into your coding agent via the Joule Studio MCP. They guide the local coding agent in building and deploying a Joule Studio-compliant solution.

- **Joule Studio CLI ([jl](https://www.npmjs.com/package/%40sap/joule-studio-cli?activeTab=readme)):** A command-line interface that enables developers to build and deploy solutions to the Joule Studio runtime

- **Joule Studio runtime:** The SAP-managed execution environment for agents, applications, workflows and MCP servers, shown as *Managed Runtimes* in the reference architecture (see below). This is where custom agents run alongside SAP-delivered Joule Agents.

- **Agent2Agent (A2A) protocol and Agent Card:** Each generated agent runs as an A2A server and publishes an Agent Card describing its capabilities.

- **Model Context Protocol (MCP) and MCP Builder:** MCP is the standard through which Joule Studio agents reach tools and business systems; MCP servers are consumed through Agent Gateway rather than called directly. The MCP Builder in Joule Studio creates new MCP servers, which are deployed to the Managed Runtimes.

- **Agent Gateway:** The central integration layer of SAP Business AI Platform for discovery and invocation of agentic resources. A2A traffic from Joule to agents and MCP traffic from agents to tools passes through it.

- **Joule Orchestrator (Agent Harness):** The reasoning and orchestration engine in Joule Work that receives the user's prompt and provides a response by using the Joule skills and by routing the request to the right Assistant or Agent. It calls deployed agents using the Agent-to-Agent (A2A) protocol through the Agent Gateway.

- **[SAP AI Agent Hub](https://help.sap.com/docs/ai-agent-hub/sap-ai-agent-hub/sap-ai-agent-hub-overview):** Governance command center that registers AI agents, AI models and MCP servers across the enterprise and runs verification workflows before they can be used in production.

- **[Ideation Agent](https://ai4u-website.cfapps.eu10-004.hana.ondemand.com/ideation-agent):** An agent that helps you to identify valuable AI use-cases and guides you from a generic business challenge to a refined intent.

## <span className="step-number">2</span> <span className="step-title">Business AI Platform Pre-requisites</span> {#2-business-ai-platform-pre-requisites}

### Commercial

- Your organization has the following commercial entitlements in place:

  - You have a valid license for an SAP product that supports Joule integration in one of the supported regions.

  - You have purchased the AI Unit SKU (8019164) or Joule Base.

  - You have an active SAP BTP Enterprise Agreement (SAP BTPEA), Cloud Platform Enterprise Agreement (CPEA), or Pay-As-You-Go for SAP BTP contract. See [What Is the Consumption-Based Commercial Model?](https://help.sap.com/docs/btp/sap-business-technology-platform/what-is-consumption-based-commercial-model?version=Cloud)

  - You have subscribed to the Joule Studio SKU (8021813). The SKU is linked to your BTPEA, CPEA, or Pay-As-You-Go contract.

### Technical

1. Provision the core components, Joule Work and Joule Studio through SAP for Me, and link them to an SAP Cloud Identity Services tenant.

2. Assign users to the user groups within the SAP Cloud Identity Services tenant. User groups joule_end_user and JouleStudioDeveloper for Joule Studio access and User group JouleStudioAdministrator for Joule Studio Admin access.

3. For the Pro-Code Flow, on the developer machine:

   - Node.js, as Joule Studio CLI is distributed as an npm package.

   - Joule Studio CLI (jl) installation from [https://www.npmjs.com/package/@sap/joule-studio-cli](https://www.npmjs.com/package/%40sap/joule-studio-cli).

   - Claude Code or OpenCode as the coding agent. Either can be used directly in the terminal or as plugins in VS Code or Cursor.

   - Python, as the agents are generated in Python.

   - Git and a remote repository (e.g., GitHub) for moving code between Joule Studio and your IDE.

Refer to [help page](https://help.sap.com/docs/joule-studio/joule-studio/provision-joule-studio) for details on provisioning.

Summary:

Users can access Joule Work through a web, desktop or a mobile client. Joule Studio is only accessible within the Joule Work Web Client. Agents are built in **Joule Studio** and deployed to the **Managed Runtimes** within **SAP Business AI Platform.** At runtime, a user request is processed by the **Joule Orchestrator**, which forwards it to the deployed agent through the **Agent Gateway.** The Agent uses an MCP server within the managed Runtime to connect to the **SAP Autonomous Suite**.

The customer-managed Global account containing *Custom Agents* is covered by the <Link to={useBaseUrl("/docs/technical-view/agentic-ai/concepts/pro-code-ai-agents")}>Pro-Code: Creating AI Agents</Link> best practice page.

Reading the diagram for a Joule Studio agent:

- **Build.** A developer builds a custom agent in Joule Studio (within Joule Work) with Intent-Based Development in the browser or through the Pro-Code Flow and optionally creates MCP servers with the MCP Builder.

- **Deploy.** Joule Studio deploys the agent, and any MCP servers it created, to the Managed Runtimes. Custom agents run there alongside SAP-delivered Joule Agents provisioned from the SAP Autonomous Suite.

- **Invoke.** A user works in Joule Work through a web, desktop or mobile client. The Joule Orchestrator (agent harness) selects the agent and calls it over A2A through Agent Gateway.

- **Act.** The agent performs CRUD operations on the **SAP Autonomous Suite** using MCP Servers running on the Managed Runtime. The MCP server in turn uses the APIs exposed from the **SAP Autonomous Suite.**

- **Trust.** SAP Cloud Identity Services authenticates the user and establishes trust across Business AI Platform, the SAP Autonomous Suite, the customer's subaccount and third-party identity providers, so the user's identity is carried through every hop.

- **Govern.** SAP AI Agent Hub discovers and governs agents and MCP servers including third-party ones. SAP Signavio Agent Mining analyzes agent behavior. SAP Cloud ALM enables observability by storing the logs of Agent executions.

The diagram focuses on runtime. At design time, Intent-Based Development additionally draws on SAP Knowledge Graph, SAP LeanIX and SAP Domain Models. In the Pro-Code Flow these are reached through a remote MCP server connected to the coding agent (see [Building AI Agents with Joule Studio](https://architecture.learning.sap.com/docs/ref-arch/219c07)).

## <span className="step-number">3</span> <span className="step-title">Key Choices and Guidelines</span> {#3-key-choices-and-guidelines}

### Identify the right business problem to solve and refine it before building it in Joule Studio

Before building a solution in Joule Studio, Business users can use the [Ideation Agent](https://ai4u-website.cfapps.eu10-004.hana.ondemand.com/ideation-agent) to identify the right business problems to solve and elaborate the problem statement into a high-quality intent. Ideation Agent can be used as a tool for individual ideation or for supporting workshops and hackathons with business users. It supports rating and prioritization of ideas and the refined intent of chosen ideas could be used as an input in Joule Studio.

### Choose between Joule Studio (SAP-managed) versus Pro-code development of Agents deployed in Cloud foundry/Kyma within Customer managed Business AI Platform

Consider the following criteria to decide between agent development and deployment in the SAP-managed Joule Studio runtime and the customer-managed Business AI Platform runtime.

| **Criteria** | **Joule Studio AI Agents (SAP-managed)** | **Pro-code development of Agents deployed in Cloud foundry/Kyma within Customer managed Business AI Platform** |
| --- | --- | --- |
| Time to first deployed agent | Fast - IBD generates code, tests and deployment config | Slower - you manage runtime, CI/CD and integration |
| Operations effort | None for infrastructure | Full: scaling, patching, monitoring, secrets |
| Joule integration | Automatic registration | Expected in future by registering the Agent in Agent Gateway |
| SAP system access | MCP via Agent Gateway is enforced | Any pattern you choose and secure yourself |
| Identity and audit | Provided by SAP Cloud Identity Service, Agent Gateway and Runtime | You implement principal propagation and audit |
| Framework and dependency freedom | Bounded by Joule Studio runtime | Unrestricted |
| Structural freedom | Keep manifests, entry point and SAP decorators intact | Unrestricted |
| Design-time business grounding | Grounded on SAP Knowledge Graph, LeanIX, SAP domain models | Not included by default |

**Recommendation:**

**Joule Studio** should be the default option for creating agents. It provides the benefits described above and is SAP's recommended environment for building agents, applications, and workflows.

**A customer-managed runtime may be chosen for following reasons:**

- The agent needs certain capabilities which are not yet available in Joule Studio. For example, connecting to third-party MCP servers or building UI applications along with Agents (status as of November 2026).

- The agent must run in a specific customer-controlled subaccount or region for compliance reasons.

- You need a framework or programming language other than the Joule Studio generated default.

### Pick the Joule Studio design-time surface based on the user persona

Both surfaces produce the same artifact, so the choice is about people and workflow:

- **Browser flow:** Preferred for business process experts who drive the intent and requirements. It is easier to start with this option, as it does not require local setup and is accessible directly within Joule Work. Developers can also start with the Browser flow but may need to switch to the Local flow for a higher degree of control.

- **Local flow:** Preferred for developers as it enables usage of an IDE and coding agent of their choice. This also enables usage of custom skills and custom MCPs in addition to the IBD skills and Joule Studio MCP. This option also allows customers to apply their own naming conventions.

- **Hybrid:** It is also possible to use a hybrid approach using both design surfaces. Capture intent and review the PRD with the business process expert in the browser, then continue specification review, code refinement and testing in the local IDE. Use the Git repository as the handoff point.

### Use Guided mode for productive Agents

Joule Studio offers two modes for building an agent: **Guided** (refine intent before building) and **Quick Create** (skip clarifying questions and start directly building the solution). In the Local flow, the Quick Create mode can be activated by using the words *Fast Track* in the input prompt.

**Recommendation:**

**Guided** mode is the preferred option especially for creating productive Agents. In Guided mode, Joule Studio asks relevant clarifying questions before it starts building. It ensures a higher-quality intent, PRD, specification and code. Result quality improves significantly when time is invested upfront in providing accurate answers to the clarifying questions.

**Quick Create** mode should only be used for demo purposes and not for building production agents.

Additional considerations:

- **State the artifact type in the intent.** If you want only an agent, say so explicitly (e.g., "Create an agent that…"). The artifact tiles in the start dialog only pre-fill the prompt, and IBD may otherwise propose additional artifacts such as workflows.

- **Clarifying answers shape the architecture.** For example, answering that the agent should run periodically typically leads IBD to add an n8n workflow for scheduling. When answering, keep the desired architecture in mind.

### Treat the Intent, PRD and Specification as Source Code

As the generated code depends on intent, PRD, and Specification, it is important to review each artifact carefully. This has a direct impact on the quality of the generated agent code.

- **Write intents that are specific.** Name the business outcome, the user role, the systems of record, the actions that need human approval, and what "done" looks like. Leverage the [Ideation Agent](https://ai4u-website.cfapps.eu10-004.hana.ondemand.com/ideation-agent) to ensure a high-quality initial Intent.

- **Review the PRD for scope.** Check goals, non-goals and acceptance criteria. Acceptance criteria should become eval cases later, so specific acceptance criteria produce better evals.

- **Review the specification for the tool inventory.** Verify every API the agent will use, which operations are reads and which are writes, where human-in-the-loop (HITL) applies, and how errors are handled. Also check the solution architecture for artifacts you did not ask for (extra workflows or MCP servers). Business users can usually review the intent and PRD but not the specification, so assign a developer as specification reviewer.

- **Push deterministic logic into tools.** Keep the agent's instructions and runtime skills limited to what genuinely needs an LLM. Put calculations, validations and rules into tool code: code is deterministic and cheaper to run than LLM reasoning, which may skip or approximate such steps.

- **Fix upstream, then regenerate.** If generated code is wrong because the specification is wrong, correct the specification rather than hand-patching the code. When you change the PRD after the solution was generated, Joule Studio enables an *Update solution* action that you trigger manually.

- **Keep specification and code in sync.** Joule Studio does not automatically update the intent, PRD or specification when code or workflow steps are edited directly. Prefer making changes through the Joule chat interface within Joule Studio because it updates all artifacts together. When you do edit code by hand, ask the chat to update the specification (and PRD) from your changes, check that it did, and commit both together. An out-of-date specification silently breaks the traceability chain, making the agent more difficult to audit.

- **Version everything.** Intent, PRD, specification, code and tests belong in the same repository. Releases created in Joule Studio become Git tags, and promotion to another tenant deploys a selected tag. The promoted solution is read-only in the target tenant, so every change goes through the development tenant.

### Set Up Landscapes and Governance from the beginning

- **Use at least two landscapes.** Provision separate non-production and production landscapes with a separate SAP Cloud identity Services tenant, Joule Work, Joule Studio and back-end systems. A third (test) landscape is optional and can be added to the same promotion pipeline.

- **As an administrator, configure Joule Studio right after provisioning.** Allow-list the LLMs that agents may use (by default all available models are enabled) and restrict the Git providers and organizations to the ones your company uses.

- **Separate building from releasing.** Development should be performed only in the non-production landscape. Only authorized users should have the roles to release a solution to the production landscape. Joule Studio in Production landscape should only be used for monitoring deployed agents or deploying agents transported from non-production landscape.

- **Automate promotion.** Connect the Git organization to both production and non-production Joule Studio tenant. Configure Git Actions to trigger a CI/CD pipeline when a solution is released in the non-production tenant. Run code reviews and quality/security scans in that pipeline and automate deployment after a successful pipeline run.

- **Complete the production checklist.** After promotion: assign the users or groups who may invoke the agent in SAP Cloud Identity Services, verify the agent in SAP AI Agent Hub (only verified agents may run in production), and monitor it in SAP Cloud ALM (AI Agent Monitoring).

## <span className="step-number">4</span> <span className="step-title">Implementation</span> {#4-implementation}

The implementation steps for Browser Flow and Local flow are explained below. Both build the same agent, so the two design-time surfaces can be compared on one business case: an agent that answers queries about products in an SAP S/4HANA system.

### Create a Solution in Joule Studio Web (Browser flow)

In the browser flow, no local setup or coding agent is required. You describe your intent in the Joule chat, and Joule Studio takes it through intent, requirements, specification, code generation, testing and deployment.

1. **Start a new solution.** In Joule Studio, the *What do you want to create?* dialog offers Agent, n8n Workflow, Application, Data Product and Extension. Choose **Agent** or describe the solution in the prompt field. If the use case spans multiple asset types, then use the generic option to describe the solution.

2. **Select Guided and state the intent.** Make sure the mode selector under the prompt field shows **Guided**, then describe the solution. For example: *Create an agent that answers queries about products in an SAP S/4HANA system.* Keep the word "agent" in the intent so IBD does not add other artifact types.

3. **Answer the clarifying questions with specifics.** Name the user role, the product information the agent must return, the system it reads from, whether the agent only reads or may also change data, and what a correct answer looks like. If a clarifying question contains an incorrect assumption, correct it instead of accepting it. Accepted assumptions flow directly into the PRD.

4. **Review the PRD.** Check goals, non-goals and acceptance criteria. Make each acceptance criterion testable, because it becomes an eval case later.

5. **Review the specification.** Check the tool inventory: which S/4HANA APIs the agent calls, that they are read operations, and how errors and empty results are handled. SAP Knowledge Graph is used for API discovery; confirm that the proposed APIs are available in your S/4HANA system.

6. **Generate and inspect the solution.** Review the generated code at a high level, the agent's prompt, model selection and the MCP tools. Try the agent in the live preview before moving on. The preview runs against mock data, and its console shows traces and logs.

7. **Run the tests and evals.** Run the generated unit tests and AI evals, and add eval cases for any acceptance criteria that are not yet covered.

8. **Deploy.** Click the Deploy button to deploy the solution to the SAP-managed Joule Studio runtime. The agent registers with Joule automatically. Make sure you are assigned to the agent in SAP Cloud Identity Services, otherwise Joule reports that you are not allowed to use it. Then test it by asking a product question in Joule Work. This is the first test against real S/4HANA data.

Note: Joule Studio coding agent stops if the browser is closed. If you need to switch to another screen on joule studio, open it in a new browser tab to ensure that the coding agent is not stopped.

To continue in a local IDE afterwards, use the Git repository as the hand-off point and carry on with the Pro-Code Flow below (the *Hybrid* pattern in Section 3).

To move the agent to production, connect the solution to your Git repository, create a release and deploy that release tag to the production tenant.

### Build an Agent with the Local flow (Joule Studio CLI and OpenCode)

The Joule Studio Local Flow runs the same IBD phases from a local terminal. The [Joule Studio CLI (jl)](https://www.npmjs.com/package/%40sap/joule-studio-cli?activeTab=readme) connects to your Joule Studio tenant, prepares the project for your coding agent and deploys the result. The coding agent, OpenCode in this example, drives IBD using the skills that jl installs. The prerequisites are listed under *Technical* in Section 2; the CLI needs Node.js 24 or later.

#### 1. Install the CLI and check the commands

```bash
npm install -g @sap/joule-studio-cli
jl --help
```

jl --help lists the command groups like login, init, solution, asset, mcp and a2a.

#### 2. Log in to your Joule Studio tenant

```bash
jl login '<joule-studio-url>'
```

Copy the URL from Joule Studio in the browser under **Settings → Develop**. The CLI stores the session in ~/.joulestudio/credentials.json; jl info shows which tenant you are connected to.

#### 3. Confirm the connection

```bash
jl solution list
```

This lists the solutions in the tenant you are logged in to. If it fails, fix the login first — the next step downloads skills from the same tenant.

#### 4. Initialize a project for OpenCode

```bash
mkdir product-query-agent && cd product-query-agent
git init
jl init opencode
```

jl init opencode downloads the Joule Studio skills from your tenant into the project (for example sap-agent-bootstrap, which scaffolds Python A2A agents) and writes an opencode.json that registers a local MCP server (jl mcp start) through which OpenCode reaches the MCP servers on your tenant. It also configures OpenCode to ask for permission before editing files or running shell commands. Use jl init claude for Claude Code instead. After a CLI update, run jl init opencode --force to refresh the skills. Do not edit the downloaded SAP skills or the generated opencode.json; add your company's own skills next to them instead.

#### 5. Start OpenCode and enter the intent

```bash
opencode
```

At the OpenCode prompt, enter the intent:

```text
Create an agent that answers queries about Products in an S/4HANA system.
```

OpenCode then works through the IBD phases with the installed skills: intent analysis, requirements, specification, code and tests. You can optionally start opencode with --auto, which approves every permission that is not explicitly denied, so the ask-first settings from jl init no longer pause the run. OpenCode edits files and runs commands, including jl, without asking. That is why the project gets its own directory and Git repository in step 4. Review the PRD, the specification and the code as Git diffs before you deploy, exactly as you would in the browser flow. Remember that code generation runs on your own coding-agent subscription. If a deployment fails, stop and read the logs instead of letting the coding agent retry in a loop.

#### 6. Deploy

In the OpenCode chat window, ask the coding agent to deploy the solution, and it deploys with the CLI. You can also run the commands yourself:

```bash
jl solution validate
jl solution deploy
jl solution deploy status
jl solution deploy logs --tail 100
```

jl solution deploy builds the solution in the current directory and deploys it to the SAP-managed Joule Studio runtime, where it registers with Joule. status and logs show the deployment job. There is no local preview in the Pro-Code Flow, so this deployment is the first point at which the agent runs.

#### 7. Test the deployed agent

```bash
jl a2a card --solution <solution_id> --asset <"asset name">
jl a2a message "Show the details of product <product-id>" --solution <solution_id> --asset <"asset name">
```

jl a2a card shows the deployed agent's Agent Card, and jl a2a message sends it a question over A2A and prints the answer. Then ask the same question in Joule Work to check the end-to-end path through the Joule Orchestrator and Agent Gateway. This requires that your user is assigned to the agent in SAP Cloud Identity Services. If the answer is wrong, ask the coding agent to analyze the deployed agent's traces.
